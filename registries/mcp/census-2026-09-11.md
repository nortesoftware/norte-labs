# Official MCP Registry — direct measurement, 2026-09-11

Full pagination of `https://registry.modelcontextprotocol.io/v0/servers` (API v0, build 1.8.1
of 2026-08-06, status "preview"), three cursor walks: `version=latest` (309 pages), all
versions (980 pages, cut short) and all versions including `status=deleted` (1,017 pages,
complete). No null cursors, no duplicate name:version pairs. Raw pages were kept in a temporary
directory and deleted when the census was done; the aggregates are in
[data/official-registry-stats.json](data/official-registry-stats.json).

What the registry counts: **metadata entries** (`server.json`) published under an authenticated
namespace. It neither hosts nor runs code. An "entry" is not a working server
([2609.10962](https://arxiv.org/abs/2609.10962): fewer than half of the npm/stdio servers
complete the handshake).

## Who publishes

- 10,510 `io.github.*` namespaces (a personal GitHub account or organization, verified through
  OAuth) → 20,781 servers (67.4 %).
- 7,842 domain namespaces (DNS/HTTP verification, one-time) → 10,049 servers. First label:
  `com` 3,493, `ai` 909, `io` 519, `dev` 408, `app` 337, `uk` 230.
- Concentration: the 3 largest namespaces publish **4,232 servers (13.7 %)** —
  `io.github.sadri-dridi` 1,798, `io.github.pipeworx-io` 1,321, `io.github.mcp-dir` 1,113. The
  20 largest add up to 6,420 (20.8 %). They are farms of generated wrappers; they distort every
  headline figure and no published work measures them as such.
- Versions: 19,642 of 31,539 names have a single version. One name
  (`io.github.brilliantdirectories/brilliant-directories-mcp`) has 1,176 versions;
  `ai.bowmark/bowmark` 762. By total entries, `io.github.cyanheads` leads with 2,142.

## What the registry does not verify (from its own documents, opened 2026-09-11)

- Publishing = proof of namespace ownership + proof of package ownership + restricted base URLs.
  No content or security review
  ([official-registry-requirements.md](https://raw.githubusercontent.com/modelcontextprotocol/registry/main/docs/reference/server-json/official-registry-requirements.md)).
- "Consumers should assume minimal-to-no moderation"; only illegal content, malware, spam and
  broken servers are removed; vulnerable servers are not
  ([moderation-policy](https://modelcontextprotocol.io/registry/moderation-policy)).
- Code scanning is delegated to npm/PyPI/Docker Hub and to the aggregators
  ([about](https://modelcontextprotocol.io/registry/about)).
- DNS verification is one-time and apex-wide: one TXT record grants `com.example.*` forever
  (issue [#1488](https://github.com/modelcontextprotocol/registry/issues/1488)); 155 entries
  with an expired domain were re-registrable
  ([AIR Security](https://www.air.security/blog-posts/mcpjacking)).
- End-to-end documented takedowns: **one** (issue
  [#1563](https://github.com/modelcontextprotocol/registry/issues/1563): published 2026-08-08,
  reported 2026-08-09, deleted 2026-09-05). The "Abuse report:" prefix the FAQ prescribes has
  never been used by any issue.
